## 어떤 작업에 [[AI 에이전트|에이전트]]가 필요한가?

에이전트가 적절한 해결책인지 판단하는 데는 2가지 핵심 결정이 있다.
- 이 작업에 [[LLM]]이 필요한가?
	- LLM은 입력이 예측하기 어렵고 다양해서 사전에 예상할 수 없는 유연한 해석이 필요한 경우에 빛을 발한다.
	- 텍스트, 이미지, 오디오 비정형 데이터 데이터를 분석해야 할 때 LLM 사용의 강력한 후보가 된다.(정확하게는 LMM, 대규모 멀티 모델)
- LLM이 필요하다면 에이전트가 필요한가, 아니면 [[워크플로]]로 충분한가?

### 에이전트가 필요한지 판단하는 기준

에이전트에는 본질적인 트레이드오프가 따른다.
- 비용이 더 든다.(여러 번의 LLM 호출)
- 지연 시간이 늘어난다.(각 추론 단계마다 응답 시간 누적)
- 오류가 전파된다.(초기 단계의 실수가 전체 과정으로 연쇄적으로 퍼진다.)

언제 에이전트를 사용해야 할 지 판단을 돕는 3가지 기준
- 작업 복잡도: 작업이 몇 단계가 필요할지 예측하기 어렵다면 에이전트가 유리하다.
- 작업 가치: 작업 완료했을 때의 가치가 추가 비용과 지연 시간을 넘어야 한다.
- 오류 비용과 탐지 가능성: 오류가 중대한 결과로 이어진다면 에이전트가 최고의 선택이 아닐 수 있다. 탐지 가능성도 중요하다(전문 지식이 필요한 영역에서는 잘못된 결과를 냈다는 사실을 알아차리지도 못할 수 있다.)

[[LiteLLM]]을 사용하는 이유
- LLM 시장은 놀라운 속도로 변하기에 처음부터 모델 유연성을 염두에 두고 설계하는 것이 중요하다.
- 같은 코드로 여러 제공자의 모델을 쉽게 전환할 수 있도록 해준다.

uv는 pip보다 빠르면서 가상 환경 관리까지 하나로 처리한다.
파이댄틱(Pydantic): 데이터 구조를 클래스로 정의할 수 있게 해주는 파이썬 데이터 검증 라이브러리
파이썬은 async/await 문법과 asyncio 라이브러리로 비동기 프로그래밍을 처리한다.

> [!code]- 실습 코드 보기
> ```python
> # 1. 환경 변수 불러오기
> from dotenv import load_dotenv, find_dotenv
>
> load_dotenv(find_dotenv())
>
>
> # 2. OpenAI SDK로 LLM 호출하기
> from openai import OpenAI
>
> client = OpenAI()
>
> response = client.chat.completions.create(
>     model="gpt-5-mini",
>     messages=[
>         {"role": "system", "content": "You are a helpful assistant"},
>         {"role": "user", "content": "What is the capital of France?"},
>     ]
> )
>
> print(response.choices[0].message.content)
>
>
> # 3. LiteLLM으로 LLM 호출하기
> from litellm import completion, acompletion
>
> response = completion(
>     model="gpt-5-mini",
>     messages=[{"role": "user", "content": "Hello!"}]
> )
>
> print(response.choices[0].message.content)
>
>
> # 4. 대화 기록을 전달해 맥락 유지하기
> messages = []
>
> messages.append({"role": "user", "content": "My name is Daehan."})
> response1 = completion(model="gpt-5-mini", messages=messages)
> messages.append({"role": "assistant", "content": response1.choices[0].message.content})
>
> messages.append({"role": "user", "content": "What is my name?"})
> response2 = completion(model="gpt-5-mini", messages=messages)
> print(response2.choices[0].message.content)
>
>
> # 5. Pydantic으로 구조화된 출력 형식 지정하기
> from pydantic import BaseModel
>
> class ExtractedInfo(BaseModel):
>     name: str
>     email: str
>     phone: str | None = None
>
>
> response = completion(
>     model="gpt-5-mini",
>     messages=[
>         {
>             "role": "user",
>             "content": "My name is John smith, my email is john@example.com, and my phone is 555-1234."
>         },
>     ],
>     response_format=ExtractedInfo
> )
>
> result = response.choices[0].message.content
> print(result)
>
>
> # 6. 비동기로 여러 요청을 동시에 처리하기 (Jupyter Notebook 기준)
> import asyncio
> from litellm import acompletion
>
>
> async def get_response(prompt: str) -> str:
>     response = await acompletion(model="gpt-5-mini", messages=[
>         {"role": "user", "content": prompt},
>     ])
>     return response.choices[0].message.content
>
>
> prompts = [
>     "What is 2 + 2?",
>     "What is the capital of Japan?",
>     "Who wrote Romeo and Juliet?",
> ]
>
> tasks = [get_response(p) for p in prompts]
> results = await asyncio.gather(*tasks)
>
> for prompt, result in zip(prompts, results):
>     print(f"Q: {prompt}")
>     print(f"A: {result}\n")
> ```

## [[프롬프트 엔지니어링]]으로 에이전트의 행동 설계하기

프롬프트의 범주
- 사용자 프롬프트: 사용자가 채팅 인터페이스에 입력하는 메시지
- 시스템 프롬프트: 개발자가 정의한 지시

시스템 프롬프트의 역할(클로드 시스템 프롬프트에서 바라본..)
- 제품 정체성 정의하기
	- 자신의 역할과 능력을 정확히 이해해야, 무엇을 할 수 있고 무엇을 할 수 없는지 사용자에게 명확히 전달할 수 있다.
- 출력 형식과 스타일 지정하기
- 허용할 행동과 거절할 요청 정하기
- 지식의 범위와 한계 알려주기

> 에이전트는 자신의 한계를 알아야 한다.
- 자신이 모르는 것을 인정하고 대안을 제안하는 에이전트가 모든 것을 아는 척하는 에이전트보다 더 신뢰할 수 있다.

챗봇과 에이전트의 근본적인 차이는 무엇인가? 

> 챗봇은 사용자와 대화하지만, 에이전트는 사용자를 대신해 일한다.

- 에이전트는 질문하기 전에 행동해야 한다. 사용자의 의도가 명확하면 허락을 구하지 말고 즉시 실행하라.
- 불필요한 도구 호출은 비용과 지연 시간을 늘린다.

> 에이전트에서는 목표가 더욱 중요하다. 에이전트의 행동은 본질적으로 예측하기 어렵기 때문이다.
- 구체적인 벤치마크가 없으면 프롬프트를 조정하고 기능을 추가하는 데 몇 주를 쓰면서도 진전이 있는지 알 수 없다.

테스트 케이스는 다음 기준을 만족해야한다.
- 명확하고 검증 가능한 답이 있어야 한다.
- 현실적인 사용자 요청을 대표해야 한다.
- 다양한 난이도를 포함해야 한다.

GAIA는 정확 일치 평가를 사용한다.
- 모델의 답은 대소문자와 공백을 무시했을 때 정답과 정확히 일치해야 한다.

`GaiaOutput.model_validate_json(content)`는 JSON 문자열을 검증하고 `GaiaOutput` 객체로 변환하는 코드다.

`tqdm_asyncio`는 비동기 작업(asyncio)의 진행 상황을 프로그레스 바로 보여주는 도구이다.

> [!code]- GAIA 평가 실습 코드 보기
> ```python
> from datasets import load_dataset
> from pydantic import BaseModel
> from litellm import acompletion
> from tqdm.asyncio import tqdm_asyncio
> import asyncio
>
>
> # 1. GAIA Level 1 검증 데이터셋 불러오기
> level1_problems = load_dataset(
>     "gaia-benchmark/GAIA", "2023_level1", split="validation"
> )
> print(f"Number of Level 1 Problems: {len(level1_problems)}")
>
>
> # 2. 구조화된 출력 형식 정의하기
> class GaiaOutput(BaseModel):
>     is_solvable: bool
>     unsolvable_reason: str = ""
>     final_answer: str = ""
>
>
> # 3. 풀이 가능 여부 판단과 최종 답변 형식을 지시하기
> gaia_prompt = """당신은 범용 AI 어시스턴트입니다. 제가 질문을 드리겠습니다.
>     먼저 현재 능력으로 이 문제를 풀 수 있는지 판단하고, 그에 따라 "is_solvable" 값을 설정하세요.
>     풀 수 있다면 "is_solvable"을 true로 설정하고 "final_answer"에 답을 작성하세요.
>     풀 수 없다면 "is_solvable"을 false로 설정하고 "unsolvable_reason"에 그 이유를 설명하세요.
>     최종 답변은 숫자 하나, 가능한 한 적은 수의 단어, 또는 숫자 및/또는 문자열을 쉼표로 구분한 목록이어야 합니다.
>     숫자를 요구받으면, 별도 지시가 없는 한 숫자에 쉼표를 넣거나 $ 또는 퍼센트 기호 같은 단위를 사용하지 마세요.
>     문자열을 요구받으면 관사나 약어(예: 도시 이름의 약칭)를 사용하지 말고, 별도 지시가 없는 한 숫자는 일반 텍스트로 표기하세요.
>     쉼표로 구분한 목록을 요구받으면 각 항목이 숫자인지 문자열인지에 따라 위 규칙을 적용하세요."""
>
>
> # 4. 문제 하나를 풀고 JSON 응답 검증하기
> async def solve_problem(model: str, question: str) -> GaiaOutput:
>     async with asyncio.Semaphore(10):
>         response = await acompletion(
>             model=model,
>             messages=[
>                 {"role": "system", "content": gaia_prompt},
>                 {"role": "user", "content": question},
>             ],
>             response_format=GaiaOutput,
>             num_retries=2,
>         )
>         finish_reason = response.choices[0].finish_reason
>         content = response.choices[0].message.content
>
>         if finish_reason == "refusal" or content is None:
>             return GaiaOutput(
>                 is_solvable=False,
>                 unsolvable_reason=f"Model refused to answer(finish_reason: {finish_reason})",
>                 final_answer="",
>             )
>         return GaiaOutput.model_validate_json(content)
>
>
> # 5. 예측값과 정답 비교하기
> def is_correct(prediction: str | None, answer: str) -> bool:
>     if prediction is None:
>         return False
>     return prediction.strip().lower() == answer.strip().lower()
>
>
> # 6. 문제별 평가 결과 기록하기
> async def evaluate_gaia_single(problem: dict, model: str) -> dict:
>     try:
>         output = await solve_problem(model=model, question=problem["Question"])
>         return {
>             "task_id": problem["task_id"],
>             "model": model,
>             "correct": is_correct(output.final_answer, problem["Final answer"]),
>             "is_solvable": output.is_solvable,
>             "prediction": output.final_answer,
>             "answer": problem["Final answer"],
>             "unsolvable_reason": output.unsolvable_reason,
>         }
>     except Exception as e:
>         return {
>             "task_id": problem["task_id"],
>             "model": model,
>             "correct": False,
>             "is_solvable": None,
>             "prediction": None,
>             "answer": problem["Final answer"],
>             "unsolvable_reason": str(e),
>         }
>
>
> # 7. 모든 문제 × 모델 조합을 실행하고 모델별로 결과 모으기
> async def run_experiment(
>     problems: list[dict],
>     models: list[str],
> ) -> dict[str, list]:
>     tasks = [
>         evaluate_gaia_single(problem, model)
>         for problem in problems
>         for model in models
>     ]
>
>     all_results = await tqdm_asyncio.gather(*tasks)
>
>     results = {model: [] for model in models}
>     for result in all_results:
>         results[result["model"]].append(result)
>     return results
>
>
> # 8. 앞의 20문제로 두 모델 평가하기 (모델명은 노트북 기준)
> MODELS = ["gpt-6-luna", "gpt-5-mini"]
>
> subset = level1_problems.select(range(20))
> results = await run_experiment(problems=subset, models=MODELS)
>
>
> # 9. gpt-5-mini의 예측과 정답 확인하기
> for result in results["gpt-5-mini"]:
>     print(f"{result['correct']}: {result['prediction']} vs {result['answer']}")
> ```

## 학습 회고

### 알게된 점
- 에이전트를 구성하는 요소를 [[AI 에이전트를 깊이 이해하기]]에서는 LLM +컨텍스트 + 도구로 봤는데 이 책에서처럼 LLM + 컨텍스트 루프로 바라볼 수 있다는 점.
- 컨텍스트 부패를 어떻게 확인했는 지 실험(단어 재현에서 평균 정규화 레벤슈타인 거리)
	- 크로마 DB를 만든 곳에서 알아냈다는 놀라운 사실!
- 파이썬의 async def이 코루틴을 만든다는 사실.
### 애매한 점
- 파이썬에서 코루틴이 진짜 어떻게 동작하는 건지 궁금하다.
### 더 알고 싶은 점
- 파이썬의 비동기 처리(async/await, asyncio 라이브러리)
- LLM 비교 사이트들의 평가 기준이 궁금하다.
- DART 공시 에이전트 꼭 다시 도전해봐야겠다.
