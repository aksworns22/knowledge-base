# 1장. AI 에이전트의 원리와 쓰임새 이해하기

> 에이전트 개발은 본질적으로 실패를 디버깅하는 일이다.

- 에이전트가 내부에서 어떻게 작동하는지 이해하지 못하면 어떤 도구를 쓰더라도 문제를 진단하기 어렵다.

> 각 구성 요소를 직접 만들어보면 직접 만든 에이전트든 물려받은 에이전트든 상관없이 에이전트 시스템의 문제를 해결하는 데 필요한 사고 모델을 갖추게 된다.

[[LLM]]의 핵심 원리: 방대한 양의 텍스트 데이터를 처리하면서 다음 단어를 예측하는 법을 배우는 것

[[AI 에이전트]]란 제어 흐름의 일부를 LLM에 넘겨, 모델이 현재 컨텍스트와 목표를 바탕으로 어떤 행동을 취할지, 언제 멈출지를 결정하게 하는 프로그램이다.
- LLM은 자율적 의사결정을 가능하게 하고, 도구는 행동 공간을 넓히며(웹 검색, 코드 실행, 데이터베이스 접근 등 외부 세계로), 루프는 그 과정을 목표에 이를 때까지 이어간다.

> 실행 흐름에 대한 통제권을 LLM에 얼마나 줄 것인가? (에이전트 vs 워크플로우)

- 이 결정은 시스템 [[신뢰성]]부터 운영 비용까지 모든 것을 좌우한다.

[[워크플로|워크플로우]](workflow): 개발자가 실행 흐름을 미리 정의하고, LLM은 그 구조 안에서 특정 단계를 수행한다.
- 핵심 특징: 예측 가능성이다. 
에이전트(agent): LLM이 자신의 과정을 동적으로 결정하며, 어떤 행동을 취할지와 언제 멈출지를 스스로 판단한다.
- 가장 높은 수준의 자율성에서는 에이전트가 사용 가능한 도구 중에서 고르기만 하는 것이 아니라 새 도구를 만든다.

워크플로우 종류
- LLM 호출: 하나의 요청에 답하기(단일 LLM 콜)
- 체인: 여러 LLM 호출을 순서대로 연결하기
- 라우터: 입력에 따라 처리 경로 선택하기

프로덕션 시스템에서 워크플로우와 에이전트의 구분이 항상 이분법적인 것은 아니다. 실제로 효과적인  아키텍처는 두 접근법을 결합하는 경우가 많다.

워크플로와 에이전트 결합으로 인한 장점
- 복잡성을 가둔다. -> 에이전트가 작동하는 위치를 제한하면 전체 시스템을 이해하고 디버깅하기 쉬워진다.
- 비용을 최적화한다. -> 에이전트 루프는 여러 번의 LLM 호출로 비용이 많이들 수 있기에 필요할 때 유연성.
- 장애에 유연하게 대처할 수 있다.

> 아키텍처 선택의 핵심은 워크플로냐 에이전트냐가 아니다. **이 시스템의 어느 지점에서 에이전트적 행동이 그 비용을 정당화할 만큼 충분한 가치를 제공하느냐다.**
